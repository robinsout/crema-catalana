# Сервер синхронизации

Сервер хранит прогресс учеников **в зашифрованном виде** и помогает устройствам с одним кодом синхронизироваться. Работает на Hetzner (`ssh hetzner`, 188.245.182.47) по адресу **https://188.245.182.47**.

## Как устроена безопасность

- **Код синхронизации** — 128 случайных бит, создаётся в браузере. На сервер он не попадает.
- Из кода в браузере выводятся (HKDF-SHA256) два независимых значения: **id хранилища** — его видит сервер — и **ключ AES-GCM 256** — он никогда не покидает устройство.
- На сервер уходит только `id` и зашифрованный блок: отметки «пройден» с временем и результаты упражнений. Последний открытый экран остаётся на устройстве.
- **Сервер не знает** ни кода, ни ключа, ни содержимого прогресса и не может его прочитать. Утечка базы раскрывает только набор зашифрованных блоков.
- Код в адресе (ссылка из QR) стоит после `#` и браузер не отправляет его на сервер; после подключения сайт убирает код из адресной строки.
- API принимает запросы только от сайта (`https://robinsout.github.io`, CORS; другие сайты получают 403), ограничивает частоту запросов (120 в минуту с адреса) и размер блока (64 КБ).
- **Удалить данные**: на странице «Синхронизация» → «Удалить данные с сервера». На устройствах прогресс остаётся.
- Если код потерян, данные на сервере никто прочитать не сможет; на устройствах прогресс остаётся, можно включить синхронизацию с новым кодом.

## Что где

| | |
|---|---|
| Код | `server/` (Node 24, `node:sqlite`, без зависимостей), контракт API — `shared/sync-api.ts` |
| На сервере | `/opt/quadern-sync` (код, только для чтения), Node — `/opt/node/sync-current` |
| База | `/var/lib/private/quadern-sync/sync.db` (SQLite, доступ только у сервиса) |
| Сервис | `quadern-sync.service`: systemd-песочница, `DynamicUser`, запись только в свою папку, сеть только localhost, `systemd-analyze security` ≈ 1.1 |
| HTTPS | Caddy (`/etc/caddy/Caddyfile` ← `deploy/Caddyfile`): сертификат Let's Encrypt на IP, профиль `shortlived` (~6 дней), продлевается сам |
| Автозапуск | `quadern-sync` и `caddy` включены (`enabled`), `Restart=always`; проверено перезагрузкой сервера |
| Мониторинг | `.github/workflows/monitor.yml`: каждый день проверяет ответ API и что сертификату осталось ≥ 3 дней; при ошибке GitHub пришлёт письмо |

## Деплой

```sh
npm run deploy:sync     # rsync server/, shared/, deploy/ → /opt/quadern-sync, затем deploy/install.sh
```

`deploy/install.sh` идемпотентный: ставит Node 24 через nvm root и копирует его в `/opt/node`, устанавливает unit и Caddy (официальный репозиторий, нужна версия ≥ 2.10 для сертификатов на IP), перезапускает сервис и проверяет здоровье.

## Полезные команды

```sh
ssh hetzner systemctl status quadern-sync caddy
ssh hetzner journalctl -u quadern-sync -f
ssh hetzner journalctl -u caddy --since today | grep -i certificate
curl https://188.245.182.47/v1/health
```

## API

`GET /v1/health` · `GET /v1/blob/:id` → `{ data, version }` · `PUT /v1/blob/:id` `{ data, version }` → `{ version }` или 409 с текущей версией · `DELETE /v1/blob/:id`. `id` — 32 hex-символа.
