# Сервер синхронизации

Сервер хранит прогресс учеников **в зашифрованном виде** и помогает устройствам с одним кодом синхронизироваться. Синхронизация запускается **только по действию ученика** (включить, подключить, «Синхронизировать сейчас»): фоновых запросов нет. Работает на Hetzner (`ssh hetzner`, 188.245.182.47) по адресу **https://188.245.182.47**.

## Как устроена безопасность

- **Код синхронизации** — 128 случайных бит, создаётся в браузере. На сервер он не попадает.
- Из кода в браузере выводятся (HKDF-SHA256) два независимых значения: **id хранилища** — его видит сервер — и **ключ AES-GCM 256** — он никогда не покидает устройство.
- На сервер уходит только `id` и зашифрованный блок: отметки «пройден» с временем и результаты упражнений. Последний открытый экран остаётся на устройстве.
- **Сервер не знает** ни кода, ни ключа, ни содержимого прогресса и не может его прочитать. Утечка базы раскрывает только набор зашифрованных блоков.
- Код в адресе (ссылка из QR) стоит после `#` и браузер не отправляет его на сервер. Сайт сразу переносит код в память и заменяет запись в истории браузера адресом без кода — ещё до того, как ученик нажмёт «Подключить».
- **Сайт** задаёт Content-Security-Policy тегом `<meta>` (Pages не умеет заголовки): скрипты, шрифты и озвучка только с самого сайта, запросы — только к сайту и серверу синхронизации, для которого он собран (`scripts/lib/csp.ts`).
- Внутри чужого фрейма страница синхронизации ничего не делает (защита от clickjacking: Pages не умеет `frame-ancestors`).
- Сохранённый и синхронизированный прогресс считается непроверенными данными: принимаются только id уроков вида `b1-04` и ключи упражнений `урок/упражнение`.
- API принимает запросы только от сайта (`https://robinsout.github.io`, CORS; другие сайты получают 403).
- **Защита от переполнения диска:** 120 запросов в минуту и 20 новых хранилищ в час с одного адреса (429); блок до 16 КБ (реальный прогресс — сотни байт) и тело запроса до 64 КБ в Caddy (413); общий объём базы до 1 ГБ — дальше новые блоки получают 507, существующие можно обновлять; блоки, которые не синхронизировались 2 года, удаляются (при старте и раз в сутки). Настройки — переменные окружения в `deploy/quadern-sync.service`.
- **Общий origin.** Все Pages-сайты аккаунта открываются с `robinsout.github.io` и видят localStorage друг друга, в том числе код синхронизации. Поэтому к ним не подключаются сторонние скрипты (риск принят осознанно, аудит M1).
- **SSH на сервере**: вход только по ключу, fail2ban, проброс портов, агента и сокетов выключен (`/etc/ssh/sshd_config.d/00-hardening.conf`).
- **CI**: GitHub Actions подключены по хешам коммитов; Dependabot раз в неделю предлагает обновления npm и Actions (`.github/dependabot.yml`).
- **Удалить данные**: на странице «Синхронизация» → «Удалить данные с сервера». На устройствах прогресс остаётся.
- Если код потерян, данные на сервере никто прочитать не сможет; на устройствах прогресс остаётся, можно включить синхронизацию с новым кодом.

## Что где

| | |
|---|---|
| Код | `server/` (Node 24, `node:sqlite`, без зависимостей), контракт API — `shared/sync-api.ts` |
| На сервере | `/opt/quadern-sync` (код, только для чтения), Node — `/opt/node/sync-current` |
| База | `/var/lib/private/quadern-sync/sync.db` (SQLite, доступ только у сервиса) |
| Сервис | `quadern-sync.service`: systemd-песочница, `DynamicUser`, запись только в свою папку, сеть только localhost, `systemd-analyze security` ≈ 1.1 |
| HTTPS | Caddy (`/etc/caddy/Caddyfile` ← `deploy/Caddyfile`): сертификат Let's Encrypt на IP, профиль `shortlived` (~6 дней), продлевается сам |
| Автозапуск | `quadern-sync` и `caddy` включены (`enabled`), `Restart=always`; проверено перезагрузкой сервера |
| Мониторинг | `.github/workflows/monitor.yml`: каждый день проверяет ответ API и что сертификату осталось ≥ 3 дней; при ошибке GitHub пришлёт письмо |
| Обновления | Caddy — через unattended-upgrades (`deploy/52unattended-caddy` добавляет его репозиторий); Node 24 — таймер `quadern-sync-update.timer` по воскресеньям ставит свежий патч и перезапускает сервис, только если версия сменилась; ОС — unattended-upgrades с перезагрузкой в 04:30 |

## Деплой

```sh
npm run deploy:sync     # rsync server/, shared/, deploy/ → /opt/quadern-sync, затем deploy/install.sh
```

`deploy/install.sh` идемпотентный: ставит Node 24 через nvm root и копирует его в `/opt/node`, устанавливает units (сервис и таймер обновления) и Caddy (официальный репозиторий, нужна версия ≥ 2.10 для сертификатов на IP), подключает автообновления Caddy, перезапускает сервис и проверяет здоровье. `install.sh --node-only` — только обновление Node. В Caddyfile `admin off`, поэтому конфигурация Caddy применяется перезапуском, а не `reload`.

## Полезные команды

```sh
ssh hetzner systemctl status quadern-sync caddy
ssh hetzner journalctl -u quadern-sync -f
ssh hetzner journalctl -u caddy --since today | grep -i certificate
curl https://188.245.182.47/v1/health
```

## API

`GET /v1/health` · `GET /v1/blob/:id` → `{ data, version }` · `PUT /v1/blob/:id` `{ data, version }` → `{ version }` или 409 с текущей версией · `DELETE /v1/blob/:id`. `id` — 32 hex-символа.
