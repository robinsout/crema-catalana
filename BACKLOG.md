# Бэклог

Принцип: строим не самолёт, а простую и удобную систему, которая дополняет учебник Passos 1 и помогает усваивать материал. При этом ею можно пользоваться и для самостоятельного изучения, без учебника. Каждую фичу делаем минимально полезной версией, по TDD и с сохранением совместимости прогресса (см. [CLAUDE.md](CLAUDE.md)).

## Порядок работ

Главное правило: **сначала меняем то, что определяет формат уроков и данных, и только потом размножаем контент.** Каждый урок, написанный в старом формате, позже придётся переносить, а адаптация под 3 языка умножает любую переделку на 4. Уроки к юнитам по запросу ученика пишутся всё время, параллельно с фичами, уже в актуальном формате.

## F-1. Уроки для носителей испанского, английского, итальянского 📝

### Зачем
Сейчас уроки написаны для русскоязычного ученика, знающего испанский. Ценность уроков — в **сравнении с родным языком**: ловушки, ложные друзья, что похоже и что нет. Поэтому уроки для других языков нужно не переводить, а **адаптировать** под родной язык ученика:
- **испаноговорящим** почти не нужно объяснять грамматику «с нуля», зато важны кастильянизмы, ложные друзья и произношение (редукция гласных, звонкое s, ela geminada);
- **англоговорящим** нужны род и артикли, спряжение, ser/estar; опираться на испанский нельзя;
- **италоговорящим** многое близко (артикль с притяжательными, ne/ci ≈ en/hi), но есть свои ловушки: `vaig parlar` против passato prossimo, ложные друзья, гласные.

### Цели
1. Ученик выбирает язык объяснений, и весь портал — интерфейс, план и уроки — показывается на нём.
2. Новый урок легко выпустить сразу на нескольких языках или сначала на одном, а остальные добавить позже.
3. Новый язык добавляется по понятному чек-листу, без изменений в коде.
4. Всегда видно, какие уроки на каком языке готовы, а какие устарели.

### Не цели
- Машинный перевод уроков «на лету».
- Перевод самих каталанских примеров: они общие для всех языков.
- Отдельная система сборки или CMS: остаёмся на статических файлах, ванильном JS и тестах на node:test.

### Архитектура: три слоя

```
locales/
  ru/ es/ en/ it/
    ui.json            строки интерфейса: «Учебный план», «Пройдено», …
    catalog.json       тексты плана: темы, грамматика, миссии; названия курса и уроков
    PROFILE.md         профиль носителя: что легко, что трудно, типичные ошибки
    lessons/<id>.html  уроки, адаптированные под этот язык
course.json            структура без текстов: id, юниты, модули, связи, даты
audio/                 общее хранилище озвучки (I-1)
```

1. **Структура курса** (`course.json`): id уроков, порядок, юниты Passos, связи `related`. Не зависит от языка; это единственное место, где появляются id. Так же как сейчас, id вечные.
2. **Тексты на языке ученика** (`locales/<lang>/`): интерфейс, тексты плана и уроки. Урок — HTML-фрагмент, как сейчас.
3. **Каталанский материал** — примеры, таблицы спряжений, озвучка — живёт внутри уроков, но озвучка общая для всех языков (I-1). Если каталанская фраза совпадает, запись переиспользуется автоматически.

`PROFILE.md` — ключевой элемент для поддержки. В нём коротко описано, чем каталанский похож на родной язык ученика и чем отличается, какие ошибки типичны и с чем сравнивать. Им руководствуются при адаптации любого урока, поэтому уроки одного языка получаются единообразными.

### Интерфейс и данные
- Выбор языка — в шапке; при первом заходе берётся из `navigator.language`, иначе английский.
- Адрес: `/<lang>/#<id>`, например `/es/#b1-04`. Сборка создаёт по странице на каждый язык, корень `/` перенаправляет на сохранённый или подходящий язык. Ссылкой на урок можно поделиться.
- Прогресс общий для всех языков (id уроков одни и те же). В localStorage добавляется **новое** поле `locale`; формат `done` и `last` не меняется.
- Урок ещё не адаптирован под язык → вместо него показывается «урок пока недоступен на вашем языке» со ссылками на готовые версии. Сломанных ссылок не бывает.

### Флоу
**А. Новый урок**
1. Добавить id и структуру в `course.json` (и в `tests/published-ids.json`).
2. Написать урок на основном языке, сейчас это `ru`.
3. Адаптировать под остальные языки по их `PROFILE.md`: каталанские примеры по возможности те же (озвучка переиспользуется), объяснения и сравнения — под родной язык.
4. `npm run audio` → `npm run check` → пуш. Можно выпустить урок только на части языков: остальные покажут заглушку, а матрица покрытия (см. В) напомнит, что осталось.

**Б. Новый язык**
1. Создать `locales/<lang>/` по шаблону: `ui.json`, `catalog.json`, `PROFILE.md`.
2. Добавить язык в список языков (одна строка в конфиге).
3. Адаптировать уроки (флоу В); пока их нет, работают заглушки.
4. Тест проверяет, что в `ui.json` и `catalog.json` есть все ключи.

**В. Адаптация существующих уроков**
- `npm run coverage` выводит матрицу «урок × язык» со статусом: ✅ готово · ⚠️ устарело · — нет.
- «Устарело» определяется автоматически: адаптированный урок хранит отпечаток версии исходного урока (`<!-- source: ru@<hash> -->`). Если исходник изменился, урок помечается ⚠️. Это предупреждение, а не падение тестов.
- Адаптируем пачками, по модулю учебника за раз.

### Шаги внедрения (каждый — отдельный PR с тестами)
1. ✅ Вынести строки интерфейса в `locales/ru/ui.json` — поведение не меняется.
2. ✅ Разделить `lessons.json` на `course.json` и `locales/ru/catalog.json`; перенести уроки в `locales/ru/lessons/`.
3. ✅ Общее хранилище озвучки (I-1).
4. Выбор языка, маршруты `/<lang>/`, заглушки, сохранение `locale`.
5. Матрица покрытия и отпечатки версий.
6. `es`: PROFILE + интерфейс + план + вводный урок. Затем `en`, `it`.

### Критерии готовности
- Язык добавляется без правок в JS.
- Сохранённый прогресс со старых версий открывается во всех языках.
- Матрица покрытия показывает реальное состояние; CI зелёный.

### Решения
- Язык интерфейса и язык объяснений — один выбор.
- Язык браузера не поддерживается → английский.

## F-2. Синхронизация прогресса между устройствами ✅

**Сделано (2026-10-03):** сервер `server/` на Hetzner за Caddy (`https://188.245.182.47`, сертификат Let's Encrypt на IP), systemd-песочница (`DynamicUser`, ≈1.1), автозапуск проверен перезагрузкой; клиент с кодом (128 бит, контрольный символ), QR со ссылкой, HKDF + AES-GCM, слияние по времени, повтор при конфликте версий; экран «Синхронизация», статус в меню; ежедневный мониторинг сертификата. Синхронизация запускается только кнопками (решение пользователя): автоматический режим отправлял запросы по кругу. Подробности и модель безопасности — `deploy/README.md`.

### Зачем
Прогресс живёт в браузере: на телефоне и ноутбуке он разный, а после очистки браузера пропадает.

### Требования
Максимально безопасно, просто и быстро; бесплатно; минимум персональных данных.

### Варианты

| | Как входит пользователь | Безопасность | Простота для ученика | Сложность для нас |
|---|---|---|---|---|
| **A. Код синхронизации** | на первом устройстве создаёт код, на втором сканирует QR или вводит код | сквозное шифрование, сервер видит только зашифрованный блок; персональных данных нет | очень просто | маленький Cloudflare Worker + KV |
| B. Passkeys | Face ID / Touch ID | очень высокая, без паролей | просто, но перенос между экосистемами (Apple ↔ Android) неочевиден | Worker + проверка WebAuthn, больше кода |
| C. Firebase / Supabase | Google или ссылка на почту | высокая, но храним почту | привычно | мало кода, зато зависимость от провайдера и персональные данные |

### Решение: вариант A, код и QR
- Код — 128 случайных бит, показывается словами или QR. Из кода выводятся два значения: **ключ шифрования** (никогда не уходит с устройства) и **id хранилища** (его видит сервер).
- Шифрование AES-GCM через WebCrypto в браузере; сервер хранит только `id → зашифрованный блок` и ограничивает частоту запросов.
- Код потерян → на устройствах прогресс остаётся, просто создаётся новый код. «Забыть устройство» = удалить код локально.
- Если позже понадобится «настоящий» вход, поверх добавляются passkeys (вариант B).

### Модель данных и слияние
- В localStorage добавляется **новое** поле `doneAt: { id: timestamp }`; `done` и `last` остаются как есть.
- Слияние по каждому уроку: побеждает более поздняя отметка. Чистая функция `mergeProgress(a, b)`, сначала тесты.
- Синхронизация при открытии страницы, после отметки урока и периодически, пока вкладка открыта.

### Шаги
Делаем сразу полную синхронизацию, без промежуточного разового переноса по QR.

1. ✅ `doneAt` и `mergeProgress` с тестами, включая данные всех прошлых версий.
2. Сервер: `GET/PUT /v1/blob/:id`, лимиты, CORS только для `https://robinsout.github.io`. Логика — переносимая функция `Request → Response` с тестами, хранилище — `node:sqlite`. Развёртывание на Hetzner: Caddy + systemd.
3. Интерфейс: «Синхронизировать устройства» → показать код и QR → на втором устройстве отсканировать QR камерой или ввести код. QR рисуется в браузере, без внешних сервисов.
4. Документ о безопасности: что хранится, что видит сервер, как удалить данные.
5. Мониторинг срока сертификата: если до истечения меньше 3 дней, это видно в CI или в письме.

<a id="f-2-server"></a>
### Сервер: Cloudflare или свой Hetzner

Серверу нужно немного: хранить зашифрованные блоки по id и ограничивать частоту запросов. Данные зашифрованы в браузере, поэтому даже взлом сервера не раскрывает прогресс; вопрос только в надёжности и в том, сколько сил уходит на поддержку.

| | Cloudflare Workers + KV | Свой сервер на Hetzner |
|---|---|---|
| Стоимость | бесплатный тариф с запасом | уже оплачен |
| Поддержка | нет: обновления, TLS, защита от DDoS — на Cloudflare | обновления ОС, TLS, бэкапы, мониторинг, перезапуски — на нас |
| Доступность | глобальная сеть, высокая | один сервер; его простой = нет синхронизации |
| Безопасность | меньше поверхности атаки | ещё один открытый сервис рядом с другими проектами на той же машине |
| Контроль и привязка | привязка к Cloudflare, но API крошечный | полный контроль |

**Решение: свой Hetzner.** Синхронизация работает в режиме «сначала локально», а данные зашифрованы в браузере. Поэтому сбой сервера не ломает портал (синхронизация просто откладывается), бэкапы не критичны (полная копия есть на каждом устройстве), утечка ничего не раскрывает. Главный аргумент за Cloudflare — «не нужно поддерживать сервер» — отпадает, потому что сервер у нас уже есть и он приведён в порядок.

Сервер подготовлен 2026-10-03: обновления и перезагрузка (до этого 713 дней без перезагрузки), вход по SSH только по ключу, fail2ban, ufw (открыты 22, 80, 443), автоматическая перезагрузка в 04:30, если её требуют обновления.

**Как разворачиваем:**
- **Caddy** — обратный прокси с автоматическим HTTPS (Let's Encrypt).
- **Сервис синхронизации** — Node 24 + `node:sqlite`, без внешних зависимостей. systemd-юнит с отдельным пользователем (`DynamicUser`), `ProtectSystem=strict`, запись только в `StateDirectory`.
- **Адрес** — `https://188.245.182.47`. Сертификат Let's Encrypt на IP-адрес (профиль `shortlived`, срок около 6 дней), Caddy получает и продлевает его сам. Ограничения: адрес привязан к IP, поэтому при смене сервера меняется адрес API (одна строка в конфиге сайта); продление проверяется мониторингом срока сертификата. Если когда-нибудь появится свой домен, переход — DNS-запись и та же одна строка.
- **Деплой** — `npm run deploy:sync` по SSH.
- Логика сервера — переносимая функция `Request → Response`: при желании её можно перенести в Cloudflare Workers без переписывания.

## T-1. Переезд на TypeScript + Vue 3 + Vite ✅

### Зачем
Сейчас сайт — ванильный JS: страница собирается строковыми шаблонами через `innerHTML`. Для чтения уроков этого хватало, но впереди интерактив: упражнения с проверкой, карточки, экран синхронизации с QR, переключатель языка. На строковых шаблонах это превращается в ручную возню с событиями и перерисовкой. Плюс у проекта появляются **контракты данных** — `course.json`, `catalog.json`, формат прогресса, протокол синхронизации, — и типы, общие для сайта и сервера, защитят их лучше, чем тесты на каждый случай.

### Принципы
- **Только рефакторинг**: поведение и внешний вид не меняются, все текущие тесты переносятся и проходят.
- **Контент не зависит от фреймворка**: уроки остаются HTML-фрагментами в `locales/<lang>/lessons/`, тексты — JSON. Будущие интерактивные блоки в уроке объявляются разметкой (например, `<div data-exercise="…">`), а Vue монтирует на них компоненты. Так адаптация уроков на другие языки не требует знания Vue.
- **Чистая логика остаётся чистой**: `storage`, `model`, `i18n`, `say` переводятся в `.ts` один к одному, без Vue. Их же использует сервер синхронизации.
- **Стандартный стек сразу**: vue-router и Pinia подключаем при переезде, а не потом. Впереди несколько экранов (язык, синхронизация, карточки) и общее состояние (прогресс, язык, настройки, синхронизация). Без них пришлось бы писать собственные упрощённые аналоги, а встраивать их позже дороже, чем сейчас.
- **Формат прогресса — наш**: стор прогресса в Pinia оборачивает `storage.ts` (контракт совместимости, `mergeProgress`). Плагины автосохранения вроде `pinia-plugin-persistedstate` не используем: они меняют формат данных в localStorage.
- CSS переносится как есть.

### Стек

- **vue-router**, режим hash (GitHub Pages не умеет серверные редиректы для режима history). Маршруты: `/:lang/plan`, `/:lang/lesson/:id`, позже `/sync`, `/review`; экраны загружаются лениво. 3. Сторы Pinia (`progress` поверх `storage.ts`, `catalog`, `settings`) с тестами.

## Идеи

<a id="i-1"></a>
### I-1. Общее хранилище озвучки по тексту фразы ✅
Сейчас озвучка разложена по урокам, и одна фраза (`dilluns`) записывается несколько раз. Предлагаю хранить файлы по хешу текста, `audio/<hash>.mp3`, с одним общим индексом. Плюсы: нет дублей между уроками и языками (для F-1 это обязательно), меньше вес сайта, новый урок озвучивается почти бесплатно. Совместимость не затронута: озвучка не хранится в прогрессе.

<a id="i-2"></a>
### I-2. Словарь урока как данные ✅
**Сделано (2026-10-03):** два слоя, как у курса — `content/vocab/<id>.json` (каталанские слова: `ca`, род, мн. число, группы; общие для всех языков и озвучки) и `content/locales/<lang>/vocab/<id>.json` (перевод, примечание, названия групп). Флаг `hasVocab` в `course.json`. Раздел «Слова урока» в конце урока, слова кликабельны для озвучки. Словари есть у уроков «Els nombres i el calendari» и «Els temps verbals» (слова-маркеры с подсказкой времени). Тесты: сервис, полнота перевода, озвучка слов, отображение, e2e и скриншоты.

Ключевые слова урока хранятся структурированно (`ca`, род, перевод на язык ученика, пример) рядом с уроком. Из них автоматически строится блок «Слова урока», а также появляются материалы для карточек (I-3) и поиска (I-7). Переводить на новые языки нужно только колонку перевода.

<a id="i-3"></a>
### I-3. Повторение слов с интервалами 💡
Мини-карточки «каталанский ↔ родной язык» со звуком по словам пройденных уроков. Простой алгоритм интервалов (Leitner, 5 коробок), 5 минут в день. Состояние хранится в localStorage новым полем, а после F-2 синхронизируется.

<a id="i-4"></a>
### I-4. Интерактивные упражнения с проверкой ✅
**Сделано (2026-10-03):** типы `fill` (вписать ответ; регистр, пробелы, апострофы, `l.l` не важны; ошибка только в ударениях — «почти») и `choice` (выбор варианта, ответ сразу). Урок остаётся HTML: `<div data-exercise="id">`, Vue монтирует упражнение через `Teleport`; данные — `content/locales/<lang>/exercises/<урок>.json`. Последний результат хранится в прогрессе (v4, поле `exercises`), слияние по времени. Переведено на интерактив: вводный урок (кастильянизмы), «Времена глаголов» (формы, выбор времени), «Числа и календарь» (числа словами, quarts). Свободный перевод оставлен со спойлерами.

Вместо спойлеров с ответами — поля ввода с мгновенной проверкой (с учётом вариантов и без учёта регистра) и выбор из вариантов. Упражнения описываются небольшой разметкой в уроке, проверка — чистая функция с тестами. Результаты учитываются в прогрессе урока.

<a id="i-5"></a>
### I-5. Путь самостоятельного изучения без учебника 💡
Режим «без учебника»: план идёт не по юнитам Passos, а по темам (знакомство → числа и время → настоящее время → …). Использует те же уроки и только задаёт другой порядок в `course.json`. Так портал становится полезен и тем, кто не ходит на курсы.

<a id="i-6"></a>
### I-6. Офлайн-режим (PWA) 💡
Service worker кэширует открытые уроки и их озвучку: можно заниматься в метро и самолёте. Иконка «на главный экран» на телефоне.

<a id="i-7"></a>
### I-7. Поиск по урокам и словам 💡
Поиск по каталанскому слову или правилу: в каком уроке встречается, перевод, звук. Индекс строится при сборке.

<a id="i-8"></a>
### I-8. Версия для печати и шпаргалки 💡
Стили для печати (без меню, таблицы целиком) и короткие шпаргалки на одну страницу: спряжения, quarts, местоимения. Удобно для занятий в классе.

<a id="i-9"></a>
### I-9. Favicon и иконки сайта ✅
**Сделано (2026-10-03):** синяя плитка-панот с цветком (`content/favicon.svg`), PNG 32×32 и квадратный `apple-touch-icon` 180×180 рендерятся из SVG командой `npm run icons` (Playwright); `theme-color`. Светлую/тёмную версию не делали: синяя плитка контрастна на обоих фонах вкладок.

Сейчас у сайта нет иконки: во вкладке браузера стоит пустой значок. Нужны: SVG-favicon в стиле сайта (мотив плитки панот из шапки или буква «Q»), который корректно смотрится в светлой и тёмной теме браузера (`prefers-color-scheme` внутри SVG); PNG 32×32 для старых браузеров; `apple-touch-icon` 180×180 для «на главный экран» на iPhone. Те же иконки потом войдут в манифест PWA (I-6). Небольшая задача, можно сделать в любой момент.
